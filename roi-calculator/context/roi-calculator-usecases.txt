1. Concept: from generic ROI → use-case-driven ROI

Upgrade idea:

Step 0 of the calculator becomes: “Which AR use case do you want to calculate?”

Each use case then:

Shows its own input fields (close to the real process)

Uses use-case-specific formulas under the hood

Outputs a breakdown: how much value from training, quality, downtime, etc.

Core ActARion use cases to include:

Error-free assembly with AR

Streamlining changeovers (SMED) with AR SOPs

Data-driven / AR-guided maintenance

Fast fault recovery (remote expert + AR)

Onboarding & training with AR SOPs

The calculator should allow:

Single use case mode: “I want ROI for AR-guided changeovers on Line 3.”

Multi use case mode: “I want to see combined ROI for assembly + changeovers + maintenance.”

All benefits roll up into the same drivers (training, quality, downtime, travel) so your overall ROI metrics stay consistent.

2. Data model & use-case formulas
2.1 Core types (domain model)

Have a pure domain module, e.g. roi/domain.ts:

export type BenefitDriver = 'training' | 'quality' | 'downtime' | 'travel' | 'throughput';

export interface GlobalInputs {
  discountRate: number;
  horizonYears: number;
  adoptionByYear: number[]; // e.g. [0.6, 0.8, 1.0]
}

export interface BenefitBreakdown {
  annual: Record<BenefitDriver, number>; // € per year per driver
  totalAnnual: number;                  // sum of all drivers
}

export interface UseCaseResult {
  id: string;
  label: string;
  benefits: BenefitBreakdown;
}

export interface ScenarioResult {
  useCases: UseCaseResult[];
  aggregated: BenefitBreakdown;
  annualCosts: number;
  oneTimeCosts: number;
  cashflows: number[];      // per year including year 0
  cumulativeCashflows: number[];
  paybackYears: number | null;
  roiHorizon: number;       // simple ROI %
}


We then define a config per use case.

2.2 Use case 1 – Error-free assembly with AR

Inputs (front-end)

unitsPerYear – number of assemblies per year

errorRateBase – current error rate (%)

errorRateAr – error rate with AR (%)

costPerError – avg cost per assembly error (€)

Optional: trainingHoursBase, trainingHoursAr, newOperatorsPerYear, operatorRate, trainerRate

Formula (domain)

interface AssemblyInputs {
  unitsPerYear: number;
  errorRateBase: number; // 0–1
  errorRateAr: number;   // 0–1
  costPerError: number;
  trainingHoursBase?: number;
  trainingHoursAr?: number;
  newOperatorsPerYear?: number;
  operatorRate?: number;
  trainerRate?: number;
}

export function calcAssemblyBenefits(i: AssemblyInputs): BenefitBreakdown {
  const errorsBase = i.unitsPerYear * i.errorRateBase;
  const errorsAr   = i.unitsPerYear * i.errorRateAr;
  const errorsAvoided = Math.max(errorsBase - errorsAr, 0);
  const qualitySavings = errorsAvoided * i.costPerError;

  let trainingSavings = 0;
  if (
    i.trainingHoursBase !== undefined &&
    i.trainingHoursAr !== undefined &&
    i.newOperatorsPerYear &&
    i.operatorRate &&
    i.trainerRate
  ) {
    const hoursSaved =
      i.newOperatorsPerYear * (i.trainingHoursBase - i.trainingHoursAr);
    trainingSavings = hoursSaved * (i.operatorRate + i.trainerRate);
  }

  const annual: Record<BenefitDriver, number> = {
    training: trainingSavings,
    quality: qualitySavings,
    downtime: 0,
    travel: 0,
    throughput: 0
  };

  return {
    annual,
    totalAnnual: Object.values(annual).reduce((a, b) => a + b, 0)
  };
}

2.3 Use case 2 – Streamlining changeovers (SMED)

Inputs

changeoversPerYear

changeoverTimeBase (minutes)

changeoverTimeAr (minutes)

costPerChangeoverMinute (€/minute, based on OEE/lost throughput)

Optional: scrap in ramp-up:

scrapCostBasePerChangeover

scrapCostArPerChangeover

Formula

interface ChangeoverInputs {
  changeoversPerYear: number;
  changeoverTimeBase: number; // minutes
  changeoverTimeAr: number;   // minutes
  costPerChangeoverMinute: number;
  scrapCostBasePerChangeover?: number;
  scrapCostArPerChangeover?: number;
}

export function calcChangeoverBenefits(i: ChangeoverInputs): BenefitBreakdown {
  const minutesSavedPerChangeover =
    Math.max(i.changeoverTimeBase - i.changeoverTimeAr, 0);
  const downtimeSavings =
    i.changeoversPerYear * minutesSavedPerChangeover * i.costPerChangeoverMinute;

  let qualitySavings = 0;
  if (
    i.scrapCostBasePerChangeover !== undefined &&
    i.scrapCostArPerChangeover !== undefined
  ) {
    const scrapSavedPerChangeover =
      i.scrapCostBasePerChangeover - i.scrapCostArPerChangeover;
    qualitySavings = i.changeoversPerYear * Math.max(scrapSavedPerChangeover, 0);
  }

  const annual: Record<BenefitDriver, number> = {
    training: 0,
    quality: qualitySavings,
    downtime: downtimeSavings,
    travel: 0,
    throughput: 0 // optionally add throughput if you want to separate that
  };

  return {
    annual,
    totalAnnual: Object.values(annual).reduce((a, b) => a + b, 0)
  };
}

2.4 Use case 3 – Data-driven / AR-guided maintenance

Main drivers: fewer breakdowns, shorter MTTR, fewer emergency visits.

Inputs

downtimeHoursBasePerYear – breakdown hours today

downtimeReductionPct – AR + data/standardisation effect

costPerDowntimeHour

Optional: emergencyVisitsPerYear, costPerVisit, visitReductionPct

Formula (reuses generic downtime + travel drivers):

interface MaintenanceInputs {
  downtimeHoursBasePerYear: number;
  downtimeReductionPct: number; // 0–1
  costPerDowntimeHour: number;
  emergencyVisitsPerYear?: number;
  costPerVisit?: number;
  visitReductionPct?: number; // 0–1
}

export function calcMaintenanceBenefits(i: MaintenanceInputs): BenefitBreakdown {
  const hoursSaved =
    i.downtimeHoursBasePerYear * i.downtimeReductionPct;
  const downtimeSavings = hoursSaved * i.costPerDowntimeHour;

  let travelSavings = 0;
  if (
    i.emergencyVisitsPerYear &&
    i.costPerVisit &&
    i.visitReductionPct !== undefined
  ) {
    const visitsAvoided =
      i.emergencyVisitsPerYear * i.visitReductionPct;
    travelSavings = visitsAvoided * i.costPerVisit;
  }

  const annual: Record<BenefitDriver, number> = {
    training: 0,
    quality: 0,
    downtime: downtimeSavings,
    travel: travelSavings,
    throughput: 0
  };

  return {
    annual,
    totalAnnual: Object.values(annual).reduce((a, b) => a + b, 0)
  };
}

2.7 Aggregation & cost side

Define a function calculateScenario:

interface UseCaseInput {
  id: 'assembly' | 'changeover' | 'maintenance' | 'fault_recovery' | 'training';
  payload: any; // or discriminated union per id
}

interface CostInputs {
  annualSoftwareCost: number;
  annualHardwareCost: number;
  annualOpexCost: number;
  oneTimeCost: number;
}

interface ScenarioInputs {
  global: GlobalInputs;
  useCases: UseCaseInput[];
  costs: CostInputs;
}

export function calculateScenario(input: ScenarioInputs): ScenarioResult {
  const useCaseResults: UseCaseResult[] = input.useCases.map(uc => {
    switch (uc.id) {
      case 'assembly':
        return {
          id: 'assembly',
          label: 'Error-free assembly with AR',
          benefits: calcAssemblyBenefits(uc.payload)
        };
      case 'changeover':
        return {
          id: 'changeover',
          label: 'AR-guided changeovers (SMED)',
          benefits: calcChangeoverBenefits(uc.payload)
        };
      case 'maintenance':
        return {
          id: 'maintenance',
          label: 'Data-driven / AR-guided maintenance',
          benefits: calcMaintenanceBenefits(uc.payload)
        };
      // fault_recovery, training, etc.
      default:
        throw new Error(`Unsupported use case ${uc.id}`);
    }
  });

  // Aggregate annual benefits across use cases
  const emptyAnnual: Record<BenefitDriver, number> = {
    training: 0, quality: 0, downtime: 0, travel: 0, throughput: 0
  };
  const aggregatedAnnual = useCaseResults.reduce((acc, uc) => {
    (Object.keys(acc) as BenefitDriver[]).forEach(driver => {
      acc[driver] += uc.benefits.annual[driver] || 0;
    });
    return acc;
  }, { ...emptyAnnual });

  const totalAnnualBenefits = Object.values(aggregatedAnnual)
    .reduce((a, b) => a + b, 0);

  const annualCosts = input.costs.annualSoftwareCost +
                      input.costs.annualHardwareCost +
                      input.costs.annualOpexCost;

  const oneTimeCosts = input.costs.oneTimeCost;

  // cashflows over horizon
  const years = input.global.horizonYears;
  const adoption = input.global.adoptionByYear;
  const discountRate = input.global.discountRate;

  const cashflows: number[] = [];
  const cumulative: number[] = [];

  // year 0
  cashflows[0] = -oneTimeCosts;
  cumulative[0] = cashflows[0];

  for (let year = 1; year <= years; year++) {
    const adoptionFactor = adoption[year - 1] ?? 1;
    const benefitsY = totalAnnualBenefits * adoptionFactor;
    const costsY = annualCosts * adoptionFactor;
    const cf = benefitsY - costsY;
    cashflows[year] = cf;
    cumulative[year] = cumulative[year - 1] + cf;
  }

  const paybackIndex = cumulative.findIndex(v => v >= 0);
  const paybackYears = paybackIndex === -1 ? null : paybackIndex;

  const totalBenefitsHorizon = cashflows
    .filter((_, idx) => idx > 0)
    .reduce((sum, cf) => {
      return sum + Math.max(cf, 0); // or more exact split
    }, 0);

  const totalCostsHorizon =
    oneTimeCosts + annualCosts * years; // rough simple ROI denominator

  const roiHorizon = totalCostsHorizon === 0
    ? 0
    : (totalBenefitsHorizon - totalCostsHorizon) / totalCostsHorizon;

  return {
    useCases: useCaseResults,
    aggregated: {
      annual: aggregatedAnnual,
      totalAnnual: totalAnnualBenefits
    },
    annualCosts,
    oneTimeCosts,
    cashflows,
    cumulativeCashflows: cumulative,
    paybackYears,
    roiHorizon
  };
}

3. Instruction for your senior programmer

You can copy-paste this as an internal spec.

Goal

Upgrade the existing AR SOP ROI calculator so that:

Users can select one or more ActARion use cases (assembly, changeovers, maintenance, fault recovery, training).

Each use case has dedicated inputs and benefit logic.

The calculator aggregates all selected use cases into a single ROI view (annual savings, payback, 3–5-year ROI).

We keep the ROI engine framework-agnostic (pure TS), with React/Next as the UI layer.

Architecture

Domain layer (/lib/roi or similar)

Pure TypeScript, no React/Next.

Contains:

Core types (BenefitDriver, BenefitBreakdown, ScenarioInputs, ScenarioResult).

Use case calculators (calcAssemblyBenefits, calcChangeoverBenefits, etc.).

Aggregation function (calculateScenario).

All amounts in € per year, no formatting.

UI layer (React, likely /app/roi-calculator page)

Multi-step wizard:

Step 0 – Select use cases.

Step 1–N – Use-case-specific inputs.

Step X – Cost inputs (licenses, hardware, implementation).

Result – Output & lead form.

State:

globalInputs, useCaseInputs[id], costInputs.

Calls calculateScenario on every significant change and renders live results.

Integration layer

Next.js API route to:

POST scenario inputs + outputs into CRM / DB.

Optionally trigger email with PDF report later.

Step-by-step implementation
Step 1 – Implement domain module

Create lib/roi/types.ts with the core types (as above).

Create lib/roi/useCases.ts with:

One function per use case returning BenefitBreakdown.

A calculateScenario function taking ScenarioInputs → ScenarioResult.

Add unit tests for each use case and basic aggregation.

Step 2 – Extend the UI: use case selection

In the ROI calculator page/component, add a first step:

const USE_CASE_OPTIONS = [
  { id: 'assembly', label: 'Error-free assembly with AR' },
  { id: 'changeover', label: 'AR-guided changeovers (SMED)' },
  { id: 'maintenance', label: 'Data-driven / AR-guided maintenance' },
  { id: 'fault_recovery', label: 'Fast fault recovery with remote expert' },
  { id: 'training', label: 'Onboarding & training with AR SOPs' }
];


Allow multi-select (checkboxes).

Initialize a useCaseInputs state object keyed by id, with sensible defaults per use case.

Step 3 – Build per-use-case input forms

For each selected use case, render a sub-step with fields tailored to that process:

Assembly: units/year, error rates, cost per error, optional training.

Changeover: changeovers/year, changeover time before/after, cost per minute, optional scrap.

Maintenance: downtime hours/year, reduction %, cost per hour, optional emergency visits.

Fault recovery: incidents/year, MTTR base vs AR, cost per downtime hour, visits.

Training: training hours base vs AR, new operators/year, hourly rates.

Use simple number inputs + helper text; we can refine UX later.

Step 4 – Hook UI to domain logic

When any inputs change:

Build a ScenarioInputs object (global, useCases, costs).

Call calculateScenario.

Render:

Annual savings by driver (training, quality, downtime, travel).

Total annual savings.

Payback (years/months).

ROI over horizon.

Keep currency formatting in the UI layer.

Step 5 – Lead capture integration

Add a lead form at the end with:

Name, Company, Email, Country, Timeline, Optional “Which line/site do you have in mind?”

On submit:

POST { inputs, scenarioResult, leadInfo } to a Next.js API route (e.g. /api/roi-lead).

API route:

Writes to CRM via webhook or DB.

Returns success; UI shows confirmation.

Step 6 – Analytics & QA

Add event tracking (e.g. window.gtag or similar) when:

User starts calculator.

User completes all steps.

Lead form is submitted.

Unit tests:

Check that use case modules behave as expected with sample inputs.

Check that aggregation sums drivers correctly.
